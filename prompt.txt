<layout_fix_brief project="TrackROI" screen="metrics_page" target_agent="opencode">

  <problem_diagnosis>
    <issue id="1">
      <cause>Both the primary KPI row (Investimento, Receita, Lucro, ROAS, ROI, CPA) and the secondary "Resumo detalhado" row (Cliques, Checkouts Iniciados, Vendas Aprovadas, Pendentes, AOV, Taxa de Conversão) use a grid with a low minmax floor (200px / 180px) and auto-fit, which forces all 6 items into a single cramped row on wide viewports. Cards end up narrow with values sitting close to the edges, and there's no visual breathing room.</cause>
      <fix_required>Cap the number of columns per row (e.g. max 4 for the primary KPI row, max 3-4 for the secondary row) instead of letting auto-fit cram every item into one line. Use a higher minmax floor (e.g. 240-260px) combined with an explicit max column count via clamp/media queries so cards keep comfortable internal spacing at any viewport width, wrapping to a second row instead of shrinking.</fix_required>
    </issue>
    <issue id="2">
      <cause>The primary KPI cards and the secondary "Resumo detalhado" cards use nearly identical visual treatment (same size, same font weight for values, same padding), so there's no hierarchy signaling "these are the headline numbers" vs "these are supporting detail" — everything reads as one flat wall of equally-important boxes.</cause>
      <fix_required>Give the primary KPI row a visually heavier treatment (larger value typography, more internal padding, slightly more prominent card background/border) and keep the secondary "Resumo detalhado" row visually lighter/more compact — so the eye naturally lands on Investimento/Receita/Lucro/ROAS/ROI/CPA first, then the supporting detail below.</fix_required>
    </issue>
    <issue id="3">
      <cause>After the two card rows, roughly half the page height is completely empty — there is no further content, chart, or visual element to use that space meaningfully, making the page feel unfinished.</cause>
      <fix_required>Fill the remaining space with content that adds real analytical value: e.g. a compact trend chart (revenue/profit over time), a small comparison view (this period vs. last period), or a breakdown by traffic source — using real data from the existing summary object, not placeholder charts. If genuinely no historical data exists yet, replace the empty void with a well-designed empty state block (not just blank space) explaining what will appear there once data starts flowing.</fix_required>
    </issue>
    <issue id="4">
      <cause>Card internal padding is minimal relative to the card's height, so label and value text sit close to the card borders, reinforcing the "squeezed" feeling even when column width is adequate.</cause>
      <fix_required>Increase internal card padding and vertical spacing between label and value, and give each card a slightly taller minimum height so the content doesn't feel pressed against the edges.</fix_required>
    </issue>
  </problem_diagnosis>

  <design_direction>
    <principle>Grids should never sacrifice comfortable spacing to fit every item in one row — wrapping to multiple rows with generous padding always beats cramming everything into a single line.</principle>
    <principle>Visual hierarchy between a "headline metrics" section and a "supporting detail" section must be expressed through typography scale, spacing, and card weight — not just section titles in text.</principle>
    <principle>Empty space on a data page is a design failure, not a neutral outcome — every remaining area should either carry real analytical content or be replaced with an intentional, well-designed empty/loading state.</principle>
  </design_direction>

  <component name="primary_kpi_grid">
    <requirement>Change grid-template-columns to something like repeat(auto-fit, minmax(240px, 1fr)) combined with a max-width constraint per card (e.g. max-width: 320px) or an explicit column-count cap via container queries/media queries, so at most 3-4 cards sit per row on typical desktop widths, wrapping to a second row for the remaining ones.</requirement>
    <requirement>Increase card min-height and internal padding; enlarge the value typography slightly relative to the current size to reinforce these as the page's headline numbers.</requirement>
  </component>

  <component name="secondary_detail_grid">

  </component>

  <component name="below_the_fold_content">
    <requirement>Add a real content block below the two metric rows: a time-series chart (revenue/profit/spend trend) rendered from actual historical data if available, or a clearly designed "aguardando dados" empty state with an icon/illustration and a short explanation — filling the remaining vertical space intentionally rather than leaving it blank.</requirement>
  </component>

<layout_fix_brief project="TrackROI" screen="connections_page" target_agent="opencode">

  <problem_diagnosis>
    <issue id="1">
      <cause>The `.connections-layout` grid uses default `align-items: stretch`, forcing every connection card to match the height of the tallest sibling. Meta Ads has rich content (upload zone, tags, table, two buttons) making it tall; Perfect Pay has almost no content (a connected email line and a sync timestamp), so it gets stretched into a mostly-empty box with its buttons floating awkwardly at the very bottom.</cause>
      <fix_required>Change the grid to size each card to its own content (align-items: start / align-items: flex-start), so cards sit at natural, independent heights instead of being force-stretched to match the tallest one.</fix_required>
    </issue>
    <issue id="2">
      <cause>A card with genuinely little content (a fully connected, healthy integration needing no action) currently looks broken/unfinished when placed next to a data-heavy card, because there's nothing designed to fill that visual space meaningfully.</cause>
      <fix_required>Redesign the "connected and healthy" state of a connection card as a deliberately compact, self-contained summary (status, account identifier, last sync, a small health indicator/sparkline, and the two action buttons directly below the summary — no forced empty space). It should look intentionally minimal, not like a taller layout with missing content.</fix_required>
    </issue>
    <issue id="3">
      <cause>The top "Atualize seus dados" hero banner has its step-progress indicator (✓ — ✓ with "Comece importando a planilha da Meta" caption) floating in the top-right corner, visually disconnected from the heading and body copy on the left — no shared baseline, no visual relationship between the two halves.</cause>
      <fix_required>Redesign the hero banner as one coherent horizontal composition: heading + description on one side, and the step progress as a clearly-grouped unit (steps, connecting line, and a single caption directly under the steps) on the other, both vertically centered against each other with consistent padding — not appearing as two unrelated blocks sharing a box.</fix_required>
    </issue>
    <issue id="4">
      <cause>The imported-reports table inside the Meta Ads card requires horizontal scrolling (visible scrollbar) because it has too many wide columns (DOS RELATÓRIOS, ENCERRAMENTO DOS RELATÓRIOS, NOME DA CAMPANHA, RESULTADOS) crammed into a card-width container.</cause>
      <fix_required>Redesign this table for its actual container width: merge "Dos relatórios" and "Encerramento dos relatórios" into a single compact date-range column (e.g. "08/06 → 04/09/2026"), truncate long campaign names with an ellipsis and a tooltip/expand-on-click for the full name, and drop or right-align "Resultados" so all columns fit without a horizontal scrollbar at the card's default width.</fix_required>
    </issue>
    <issue id="5">
      <cause>Button placement is inconsistent between the two cards: Meta Ads has "Importar dados" (filled) directly above "Testar importação" (ghost) right after the table; Perfect Pay has "Reconectar" (filled) and "Testar conexão" (ghost) side by side at the very bottom of a mostly empty card. There's no shared visual anchor point for actions across card types.</cause>
      <fix_required>Establish one consistent action-bar pattern for every connection card, regardless of integration type or state: primary action (filled, purple) and secondary action (ghost) always sit inside a footer region with the same padding, alignment (side-by-side, left-aligned), and vertical position relative to the card's own content — never at a distance dictated by an unrelated sibling card's height.</fix_required>
    </issue>
  </problem_diagnosis>

  <design_direction>
    <principle>Every card must size itself to its own content. Visual balance between cards in the same row is achieved through consistent internal padding, typography scale, and a well-designed compact state — never through forcing equal container heights.</principle>
    <principle>A "fully connected, no action needed" state is not an empty version of a "needs configuration" state — it is its own deliberately designed, confident, minimal state (think of how Stripe or Vercel show a healthy connected integration: compact, clear, calm, with a green accent and a couple of soft supporting metrics — not blank space).</principle>
    <principle>Group visually related elements (a heading and its supporting UI, like the hero title and the step progress) so they read as one composition, not two separately-positioned blocks that happen to share a container.</principle>
  </design_direction>
