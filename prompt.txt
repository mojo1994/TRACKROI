  <problem_diagnosis>
    <issue id="1">
      <cause>Cards inside the "Resumo detalhado" grid rows are rendering with no visible gap between them — borders touch or nearly touch adjacent cards, making the row look like one solid glued block instead of distinct cards. This suggests the grid's `gap` value is either too small, being overridden, or the card's own border/margin is collapsing against its neighbor.</cause>
      <fix_required>Ensure a consistent, visible gap (e.g. 16-20px) is applied via CSS Grid's `gap` property on the container — not via individual card margins, which can collapse or behave inconsistently. Verify no conflicting margin/border-collapse rule is neutralizing that gap.</fix_required>
    </issue>
    <issue id="2">
      <cause>The primary KPI grid uses `repeat(auto-fit, minmax(...), 1fr)`, so when the item count (5 cards: Investimento, Receita, Lucro Bruto, ROAS, ROI) doesn't evenly divide into the computed column count, the last item (CPA) wraps alone onto a new row and — because auto-fit stretches each column to 1fr — it either shrinks to a narrow orphaned box or leaves a large empty gap beside it, depending on how the browser resolves the remaining columns.</cause>
      <fix_required>Either (a) set an explicit, fixed number of columns for this specific grid (not auto-fit) so the layout is predictable and the last row's item spans proportionally, or (b) use `grid-auto-flow: dense` combined with the orphaned item spanning multiple columns on its own row (e.g. `grid-column: span 2` or `span full-width` when it's the sole item in the last row), or (c) switch this specific KPI row to flexbox with `flex-wrap: wrap` and each card given a fixed `flex-basis` plus `flex-grow: 1`, so a lone last-row item still grows to fill the remaining row width instead of floating small with dead space beside it.</fix_required>
    </issue>
  </problem_diagnosis>

  <design_direction>
    <principle>Every grid of cards must have a clearly visible, consistent gap between items — cards should always read as distinct, separate units, never as a single fused block.</principle>
    <principle>A grid must handle non-even item counts gracefully: a lone item in the last row should either expand to a sensible width (not a narrow orphan) or the grid should reflow to keep rows visually balanced — never leave a large arbitrary empty gap next to a shrunken card.</principle>
